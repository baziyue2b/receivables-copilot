# 催收优先级功能设计

日期：2026-10-07

## 目标

为 Receivables Copilot 增加客户级催收优先级清单。系统使用 Pandas 进行确定性评分，大模型只负责调用工具和解释结果，不参与财务分数计算。

## 架构

- `src/analytics.py` 新增 `collection_priority_summary(frame)`。
- `app.py` 新增“催收优先级”展示区域。
- `src/tools.py` 新增 `get_collection_priorities(limit=10)`。
- `tests/` 增加评分、排序、工具和页面测试。
- 现有数据读取、报告和风险规则保持不变。

## 数据流

账单明细先按客户汇总，再计算优先分数、优先等级、主要原因和建议动作。结果同时供 Streamlit 页面与 Agent 工具使用。

## 评分规则

每个客户满分 100 分：

- 逾期严重度 40 分：`min(最大逾期天数 / 180, 1) * 40`
- 金额敞口 30 分：`客户未收金额 / 本批客户最高未收金额 * 30`
- 未收比例 20 分：`客户未收金额 / 客户总账单金额 * 20`
- 逾期账单率 10 分：`当前逾期未结清账单数 / 客户账单总数 * 10`

最终分数保留一位小数。

## 优先等级

- 70 至 100：紧急
- 45 至 69.9：高
- 20 至 44.9：中
- 0 至 19.9：低

## 建议动作

- 紧急：当天电话催收，并升级负责人。
- 高：2 个工作日内联系，确认付款计划。
- 中：发送提醒，每周跟进。
- 低：常规监控。

## 特殊情况

- 已全部回款客户得分为 0。
- 所有客户未收金额均为 0 时，金额敞口得分为 0。
- 分数相同时，依次按未收金额和最大逾期天数降序排列。
- 所有计算结果必须可由原始账单数据复现。

## 页面

在风险图表下方新增“催收优先级”区域，默认展示前 10 名客户。

表格字段包括：排名、客户名称、优先分数、优先等级、未收金额、最大逾期天数、主要原因、建议动作。

Agent 支持问题：“今天最应该优先催收哪些客户？”

## 测试

测试覆盖评分公式、全额回款、除零处理、排序规则、工具返回数量和 Streamlit 页面渲染。

## 不在本次范围

本次不加入人工调整权重、数据库、短信发送、邮件发送或自动执行催收操作。

## 验收标准

- 页面能够展示客户级催收优先级前 10 名。
- Agent 能通过工具返回相同的优先级结果。
- 无 Ollama 时，页面清单仍然正常工作。
- 所有自动化测试通过。
